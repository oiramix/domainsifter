## Architectural changes shipped today

### 1. Pipeline persistence (Wave 1.5)

Each daily run now produces three buckets — today's new drops, carryover that's still absent from today's zone (re-validated by zone membership, not RDAP), and removed entries (registered or > 14 days old). Carryover skips enrichment / filter / score; their data was captured on first appearance and is stable.

**New module:** `scripts/carryover.py` with pure functions: `load_existing`, `filter_by_age`, `validate_against_zone`, `annotate_today_drops`, `annotate_carryover_days_listed`, `merge`.

**Pipeline reorder:**
```
existing → filter_by_age(<= 14 days) → collect_drops(carryover_candidates=fresh)
                                           ↓
                            (per-TLD validate against today_set)
                                           ↓
              today_drops + retained_carryover (validated or fail-open)
                                           ↓
              [normal pipeline runs ONLY on today_drops]
                                           ↓
                  annotate(today, days=0) + annotate(carryover, days=...)
                                           ↓
                                       merge → write
```

**Memory note:** carryover validation runs INSIDE `collect_drops`'s per-TLD loop because `today_set` can be 10–50M apex names per TLD; holding all 13 in memory simultaneously would not fit on the 7 GB GHA runner.

**Edge cases handled:**
- TLD whose zone download fails → carryover for that TLD passes through unvalidated, `last_validated_date` unchanged. Ages out naturally if failure persists 14 days.
- Domain in BOTH today's drops AND carryover (rare — registered then dropped same week) → today's entry wins fully, no field merge.
- Pre-persistence entries (no `first_seen_date`) → migration treats as `first_seen_date = today`. They survive the migration day cleanly and age naturally.

### 2. Frontend two-card layout

DomainTable.astro split into:
- **Card 1** "Today's drops" — domains with `days_listed === 0`, 7 columns
- **Card 2** "Still available" — `days_listed > 0`, 8 columns (extra "Listed" col next to Dropped)

Shared search + TLD filter at top applies to both cards simultaneously. Per-card sort state via `sortState[scope].key/dir`. Differentiated empty-state copy: "No new drops met our quality bar today. Check the still-available list below." vs. "The rolling list builds up over time — domains that survive today's check stay here for up to 14 days."

### 3. Table → CSS Grid

The original `<table>` markup couldn't honour content-sized columns: `width: 100%` + `table-layout: auto` either distributed slack evenly (no width hints → big gaps) or dumped all slack into the unconstrained column (one width hint → one bloated column). Tables are the wrong primitive when one column needs to absorb slack.

CSS Grid replacement: each row is its own grid container with an identical `grid-cols-[200px_80px_…_1fr]` template; columns align across rows because templates match. Domain through Verdict are content-sized fixed pixels with comfortable padding; Register is `1fr` and absorbs all card slack — that's intentionally where the inline popover renders when triggered.

Semantics preserved via `role="table"/row/cell/columnheader"` so screen readers still announce as tabular data.

### 4. Inline popover, not absolute

Register cell is a flex container `[button | popover-icons]`. Popover starts `hidden` (display: none); JS toggles `flex` on open so it lays out inline next to the button using the same 1fr slack space the cell already owns. Killed three classes of bug at once:
- No `<td>`-as-containing-block inconsistency (was a real issue per build inspection on April 28-30)
- No overflow-clip from the `overflow-y-auto` wrapper
- No overlap with neighbouring columns regardless of card width

The old three-card "How it works" had Step 2 visibly longer than Steps 1 and 3, breaking the visual grid. Six cards walk the actual pipeline order: Catch → Filter → Verify → Enrich → Score → Publish. New SVG icons for the four added stages (shield-check, database, bar-chart, file-check). Responsive: 1×6 mobile, 2×3 tablet, 3×2 desktop.

### 6. Enrichment hardening (timeout + retry)

Wayback CDX and crt.sh routinely take 15–30 s under peak load. The 10 s default timeout was too aggressive — caused ~80% Wayback failures on 2026-04-30 morning. Two changes:
- **Per-enricher timeout override** via `config.api_request_timeout_seconds.{wayback,crtsh}: 60`. Other enrichers (RDAP / OPR / blocklists) keep the 10 s default — wall-clock budget is more precious than coverage there.
- **`retry_on_timeout` helper** in `_circuit_breaker.py`. Retries ONLY on `ConnectTimeout` / `ReadTimeout` / `Timeout`; other failures (`HTTPError`, `ConnectionError`, `JSON` errors) propagate immediately. 3 attempts max, 5 s + 15 s backoff. One breaker failure recorded per FINAL failure, not per attempt.

### 7. Pacing diagnostic verdict

`config.diagnostic_logging` flag added; flips throttle + wayback + crtsh loggers to DEBUG. Standalone harness ran 20 sequential calls per host through the production throttle and recorded inter-request gaps. Verdict: **100% compliance, 0 bursts.** Wayback 503s / crt.sh 502s are external-service degradation, not pacing failure. The throttle fix from 2026-04-30 morning (multiplicative jitter, single-shot reserve-then-sleep) holds.
